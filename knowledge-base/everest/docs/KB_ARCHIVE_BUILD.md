# Сборка ZIP-архива Базы знаний Bitrix24 — Технический справочник «Эверест»

`scripts/kb-archive-builder.py` собирает `manifest.json` (упакованный в ZIP) из
полного экспорта Landing-сайта Bitrix24 (`landing.site.fullExport`) для импорта
через **Сотрудники → База знаний → ⚙️ → Импорт Базы знаний → Загрузить ZIP**.

## Режим безопасности

Скрипт всегда требует входные данные явно:

- `--input <файл>` — офлайн-режим. Загружает локальный JSON-экспорт
  (результат `landing.site.fullExport`), без обращения к Bitrix24. Используется
  по умолчанию для разработки, тестов и проверки преобразований.
- `--execute --site-id <ID>` — реальный вызов `landing.site.fullExport`.
  Возможен только при одновременном выполнении условий:
  1. Установлен `BITRIX24_WEBHOOK_URL` (HTTPS).
  2. Установлен `BITRIX24_EXPORT_CONFIRM=true`.

Без выполнения этих условий скрипт завершается с ошибкой и ничего не пишет.

## Офлайн-сборка (без credentials)

```bash
python knowledge-base/everest/scripts/kb-archive-builder.py \
  --input site-export.json \
  --output kb_everest_podshipniki.zip
```

## Реальная сборка из живого сайта

```bash
export BITRIX24_WEBHOOK_URL
BITRIX24_EXPORT_CONFIRM=true \
python knowledge-base/everest/scripts/kb-archive-builder.py \
  --site-id 109 \
  --execute \
  --output kb_everest_podshipniki.zip
```

Дополнительные параметры:

- `--scope` — внутренний scope лендинга для экспорта, по умолчанию `knowledge`.
- `--sections` — путь к JSON со структурой навигации (по умолчанию
  `source/kb_archive_sections.json`).
- `--name`, `--description` — название и описание базы знаний в манифесте.
- `--base-url` — старый абсолютный префикс ссылок, который заменяется на `/`
  (по умолчанию `https://ewerest.bitrix24.ru/everest-bearing-kb/`). Пустая
  строка отключает замену ссылок.

## Что делает скрипт

1. **Метаданные**: устанавливает `type = "knowledge"`, название, описание и
   тему оформления (`ADDITIONAL_FIELDS`: цвета, шрифты).
2. **Ссылки**: заменяет абсолютные ссылки на старый домен относительными
   (`/{code}/`).
3. **Пустые страницы**: страницы без блоков (`items = {}`) заполняются
   шаблонной заметкой со статусом «нет данных».
4. **Главная страница**: на странице `LANDING_ID_INDEX` добавляется блок
   «Содержание справочника» со ссылками на все разделы и страницы из
   `source/kb_archive_sections.json`.
5. **Навигация**: в конец последнего текстового блока каждой страницы
   добавляется блок навигации со ссылкой на главную и названием раздела.
6. **ZIP**: результат упаковывается в один файл `manifest.json` внутри ZIP.

## Структура навигации

`source/kb_archive_sections.json` описывает 12 разделов справочника и раздел
«Сопутствующая продукция» — каждая запись содержит код страницы (`code`) и
заголовок (`title`), используемые для оглавления главной страницы и
хлебных крошек навигации.

## Запреты

- Не хранить `BITRIX24_WEBHOOK_URL` в репозитории.
- Не коммитить токены, пароли, webhook URL, ID пользователей и production
  credentials.
- Не запускать `--execute` без действующей ротации вебхука и без проверки
  итогового ZIP в офлайн-режиме.
- Импорт в Bitrix24 пересоздаёт страницы с новыми ID — перед загрузкой ZIP
  проверить содержимое `manifest.json` локально.
